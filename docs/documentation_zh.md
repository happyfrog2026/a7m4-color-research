# 双语文档维护

[English](documentation.md) | 简体中文

## 文件组织

- 根目录保留英文 `README.md` 和简体中文 `README_zh.md`。
- 项目自有说明放在 `docs/`，主题名使用小写，例如 `helper-guide.md` 与 `helper-guide_zh.md`。
- 每页在标题下方链接到另一语言版本；同一语言内的已配对说明互链也保持该语言。
- [documents.json](documents.json) 是文档配对与图表导出的唯一登记表，新增主题先登记。
- `LICENSE` 和上游许可、声明保留原位置及原语言；不翻译冻结的源码摘录。

## 更新一个主题

1. 同一项变更同时更新两种语言。可以先写中文草稿，但两版都经核对后才作为完整翻译发布。
2. 两版的操作、支持范围、提醒和结果含义保持一致；标识符、命令示例、schema 与文件名不翻译。
3. 共同事实以代码或确认记录为依据；README 不再各自复制一套完整流程，而是链接到对应指南。
4. 图表在 Markdown 中编辑；导出文件和文件清单由工具生成，不手改。
5. 运行下面两条命令，并在提交前对照检查双语差异。

```sh
python3 tools/docs.py sync
python3 tools/docs.py check
```

这些命令只处理仓库文档、图表与文件清单，不连接相机，也不导出用户日志。

## 自动检查

检查器核对配对登记、文件命名、顶部语言互链、本地链接目标及锚点、同语言说明互链、标题结构，以及相同的 Shell／JSON 示例；也核对图表导出、未改动的源码摘录索引和包文件摘要。GitHub 工作流在 push 与 pull request 上运行同样的检查。

自动检查只能发现结构不同步，不能证明翻译准确或机身行为。审阅者仍须对照含义，并核对事实来源。

## 代码注释与例外

新增代码注释和 docstring 使用英文。界面文字、报错与 CLI 帮助字符串属于用户可见内容，按需要保留中文；上游注释、版权和许可原文保留不变。

源码摘录有独立版本与来源记录。维护文档不意味着可以修改该快照，或通过重算索引掩盖源码变化。
